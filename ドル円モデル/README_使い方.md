# ドル円 金利差モデル — 使い方

日米金利差からドル円の妥当水準を推定し、イベントのシナリオを計算し、方向性をスコア化するツール一式です。
Excel版とPython版があり、**同じ計算式**を使っているので、どちらで動かしても同じ数字が出ます（検証済み）。

---

## 同梱ファイル

| ファイル | 中身 |
|---|---|
| `fetch_data.py` | **データ自動取得**。FRED＋財務省から落として1本のCSVにまとめます |
| `ドル円_金利差モデル.xlsx` | Excel版。日々の運用用。数式がすべて見えます |
| `usdjpy_model.py` | Python版。ローリング回帰・バックテスト・グラフ出力まで |
| `データ_テンプレート.csv` | 入力CSVの列の並び見本（1行目がヘッダー） |
| `html_report.py` | **Webページ出力**。結果を1枚のHTMLにまとめます（usdjpy_model.py から呼ばれます） |
| `usdjpy_ohlc.csv` | **ローソク足用の四本値**（始値・高値・安値・終値）。あればWebページの先頭がローソク足になります。無くても動きます |
| `demo_*.png` | Python版をデモ実行したときの出力グラフ |

## いちばん最初にやること

データがなくても、Python版はすぐ動きます。まずこれで挙動を見てください。

```bash
pip install pandas numpy matplotlib
python3 usdjpy_model.py --demo
```

（データを自動取得してすぐ本番で動かすなら `python3 usdjpy_model.py --fetch`）

合成データで全モジュールが走り、`output/` にグラフ4枚とレポートが出ます。
**合成データは「乖離が必ず平均に戻る」ように人工的に作ってあるので、バックテストの成績は
実データより大幅に良く出ます。** 数字の良さではなく、検証の手順のほうを見てください。

## データの自動取得（推奨・1コマンド）

```bash
python3 usdjpy_model.py --fetch
```

これだけで、FRED と財務省から直近4年分を落として `data.csv` に保存し、
そのまま分析とグラフ出力まで走ります。**APIキーもアカウント登録も不要**です。

取得だけしたいときは:

```bash
python3 fetch_data.py                                   # 直近4年 → data.csv
python3 fetch_data.py --start 2016-01-01 --out long.csv # 期間を指定
```

| 取得元 | 系列 | URL |
|---|---|---|
| FRED（米セントルイス連銀） | ドル円 / 米2年債 / 米10年債 / VIX | `fred.stlouisfed.org/data/<系列ID>.txt`（軽い静的ファイル。駄目なら `fredgraph.csv` に自動フォールバック） |
| 財務省 国債金利情報 | 日本2年債 / 日本10年債（昭和49年〜） | `mof.go.jp/jgbs/reference/interest_rate/data/jgbcm_all.csv` |

うまく落ちてこないときは、まず疎通確認をしてください。

```bash
python3 fetch_data.py --probe          # どの通信方法でどのURLに届くかを一覧表示
python3 fetch_data.py --transport curl # 通る方法が分かったら固定する
```

通信は **requests → urllib → curl** の順に自動で試します。curl は `--http1.1` を
強制しています（FREDのCDNがHTTP/2で `stream not closed cleanly (err 92)` を
返すことがあり、HTTP/1.1に落とすと通るため）。

日米で休場日が違うため片方だけ欠ける日がありますが、前日値で自動補完します。
財務省CSVはShift-JISで日付が和暦（`R8.9.4` など）ですが、これも自動で西暦に変換します。

> **検証状況について正直に書いておきます。**
> パース処理（和暦の変換・列の対応・欠損の補完・出力形式）と、3つの通信方法の
> 切り替えは検証済みです。ただし**FRED・財務省への実際のダウンロードは未検証**です
> （作成した環境からこの2サイトへの通信が遮断されていたため）。
> エラーが出たら `--probe` の出力をそのまま教えてください。
>
> どうしても通らない場合は、両サイトからブラウザで手動ダウンロードして
> `--fred-file` / `--jgb-file` に渡せば、同じ処理が使えます。

### Excelを「更新ボタン付き」にする（任意）

Excelだけで完結させたい場合は、Power Query を使うと更新ボタンが作れます。

1. Excelで **データ → データの取得 → その他のデータソースから → Web から**
2. URLに以下を貼る（期間は書き換えてください）
   ```
   https://fred.stlouisfed.org/graph/fredgraph.csv?id=DEXJPUS,DGS2,DGS10,VIXCLS&cosd=2022-01-01
   ```
3. 読み込み先を「データ」シートに指定
4. 以後は **データ → すべて更新** の一発で最新化されます

財務省のCSVも同じ手順で追加できますが、Shift-JISと和暦の変換が必要なので、
`fetch_data.py` を使うほうが簡単です。

## 手動で集める場合（すべて無料・所要5分）

| 系列 | 入手先 | 手順 |
|---|---|---|
| ドル円 / 米2年債 / 米10年債 / VIX | [FRED](https://fred.stlouisfed.org/) | `DEXJPUS`, `DGS2`, `DGS10`, `VIXCLS` を検索。グラフ画面の **Edit Graph → Add Line** で4系列を1つにまとめ、**Download → CSV** |
| 日本2年債 / 日本10年債 | [財務省 国債金利情報](https://www.mof.go.jp/jgbs/reference/interest_rate/) | 年度別CSVをダウンロード。`2年` と `10年` の列を使う |

FREDは欠損日を `.` で出力しますが、両方のツールとも自動で処理します。
日米の祝日が違うので片方だけ空く日がありますが、前日値で埋めるので問題ありません。

### CSVの形

列名はこのとおりにしてください（`データ_テンプレート.csv` と同じ）。

```
date,usdjpy,us2y,jp2y,us10y,jp10y,vix
2024-01-02,141.90,4.33,0.05,3.94,0.62,13.20
```

- **必須**: `date`, `usdjpy`, `us2y`, `jp2y`
- **任意**: `us10y`, `jp10y`, `vix`（空欄でも動きます）
- 日付は**古い順**に並べてください
- **最低370行**（≒1年半）必要です。2〜4年分あると安定します

## ローソク足について

Webページの先頭「01 — Price Action」は、`data.csv` と同じフォルダに
`usdjpy_ohlc.csv` があるときだけ表示されます。無ければ従来どおり折れ線だけになります。

    date,open,high,low,close
    2026-09-08,153.827,154.423,152.881,153.444

**注意点**

- 表示するのは直近2年ぶんだけです。全期間を1枚に詰めると1本1px以下になって
  潰れるためです（期間は `html_report.py` の `CANDLE_YEARS` で変更可）。
- 同じ図に日米の2年債・10年債の金利差を右軸で重ねています。
- 赤が陽線（終値>始値＝その日は円安）、青が陰線（円高）。ページの他の図と同じ色分けです。
- スマホでは図の中を横スワイプできます。
- 四本値は Yahoo の1時間足をUTCの日付で日次にまとめたものです。
  モデル本体が使う `data.csv` の終値は FRED（NY正午の仲値）なので、
  **同じ日でも0.1円前後ずれます**。ローソクは値動きの形を見るためのもの、
  数値の根拠は `data.csv` 側、と分けて考えてください。
- Yahooの「日足」APIは終値が始値のコピーになっている日が多く、そのままでは
  ローソク足に使えません。必ず1時間足から組み直してください。

## CPI・雇用統計のセクション（02・03）について

`data.csv` と同じフォルダに `us_macro.csv` があるときだけ表示されます。

    date,cpi_yoy,core_cpi_yoy,cpi_mom,core_cpi_mom,payrolls_chg,unemp,ahe_yoy,
    cpi_release,cpi_yoy_f,core_cpi_yoy_f,cpi_mom_f,core_cpi_mom_f,
    jobs_release,payrolls_chg_f,unemp_f

- `date` は**対象月の1日**です（発表日ではありません）。
- 末尾が `_f` の列が**市場予想（コンセンサス）**です。表では指標ごとに
  「実績／市場予想／差」の3列で並び、差には色が付きます。
  **上振れが赤（ドル高・円安方向）、下振れが青**。
  ただし**失業率だけは色が反転**します（低いほうが強い統計のため）。
- `cpi_release` / `jobs_release` は**発表日**です。実績がまだ無く予想だけある月は
  表の先頭に色つきで「◯/◯ 発表予定」と出ます。図のほうにも白抜きの丸で予想が乗ります。
- `_f` 列や発表日の列は**無くても動きます**（その場合は「—」になります）。
- 予想値の出どころは Trading Economics のエコノミスト調査です。
  過去ぶんの無料アーカイブが無いため、**予想が入るのは直近の2〜3回だけ**です。
  遡って埋めることはできません。

## 金融政策のセクション（04）について

`policy.json` があるときだけ表示されます。政策金利・1年債・2年債の利回りと、
FOMC／日銀の会合日程を入れます。

- 「織り込み」は `（1年債 − 現在の翌日物金利）÷ 0.25` で出しています。
  **期間全体の平均**であって、「次回会合で何％の確率で利上げ」ではありません。
- 債券利回りにはターム・プレミアムが含まれるので、実際の織り込みは
  ここで出る数字よりやや小さめになります。

## 自動更新について

`~/株分析/run_daily.sh` に組み込んであります。**平日の16:30／19:00／22:00**に
株チャートと一緒に走り、最後に GitHub Pages まで自動で公開されます。
手で何かする必要はありません。

手動で動かしたいとき:

    bash ~/株分析/run_usdjpy.sh                 # 取得 → 再生成 → 公開用にコピー
    bash ~/株分析/run_usdjpy.sh --no-publish    # 様子見（data/charts には触らない）

ログ: `~/株分析/logs/usdjpy_YYYYMM.log`（月ごと）。
うまくいかない日があってもここを見れば分かります。

### 自動で更新されるもの／されないもの

| | 自動 | 取得元 |
|---|---|---|
| ドル円の終値・金利（data.csv） | ○ | FRED ＋ 財務省 |
| ローソク足（usdjpy_ohlc.csv） | ○ | Yahoo Finance（1時間足） |
| タイルの実勢レート | ○ | Yahoo Finance（実行時点） |
| 政策金利・1年債・2年債（policy.json） | ○ | FRED ／ 財務省 ／ 日本銀行 |
| 米CPI・雇用統計の**実績**（us_macro.csv） | ○ | FRED |
| 米CPI・雇用統計の**市場予想**（`_f` 列） | **×** | 手で入力 |
| 発表日（`cpi_release` / `jobs_release`） | **×** | 手で入力 |
| FOMC・日銀の**会合日程**（meetings） | **×** | 手で入力 |

下3つは無料で機械的に取れる出どころが無いため手動です。ただし
**放っておいても黙って壊れないように**してあります。会合日程がすべて
過去になったらログに警告が出ますし、米EFFRが `target_range` の外に出たとき
（＝FOMCが動いた可能性）も警告します。

### 壊れないようにしてあること

- **取得元ごとに独立して失敗します。** 財務省が落ちていてもFREDぶんは更新し、
  ページは必ず作り直します。全部落ちたときだけ異常終了します。
- **既存データが減る更新は捨てます。** 行数が減る・最終日が戻るような結果は
  書き込みません。サイトの仕様変更で空データが返ってきても履歴は壊れません。
- **書き込みは一時ファイル経由**で、直前の版は `.bak` に残ります。
  何かおかしくなったら `data.csv.bak` などに戻せます。
- 解析部分のテストが同梱してあります。サイトの様式が変わったか調べたいときは

      cd ~/株分析/ドル円モデル && python3 test_update_usdjpy.py

  通信はしないので、いつ実行しても安全です。

## Python版の使い方

```bash
# データ取得から分析まで一気に
python3 usdjpy_model.py --fetch

# 手元のCSVで分析
python3 usdjpy_model.py --csv data.csv

# 現在値を手入力する（取得時刻も一緒に残す）
#   --spot-asof を付けると、ページの「ドル円（実勢）」に時刻が表示されます。
#   省略すると実行時刻（日本時間）が入ります。
python3 usdjpy_model.py --csv data.csv --spot 153.38 --spot-asof "2026-09-10 08:36 JST" --html

# イベント当日：織り込み確率を指定してシナリオを更新
python3 usdjpy_model.py --csv data.csv --spot 154.4 --p-fomc-hike 0.55 --p-boj-hike 0.60

# 例外フィルターを効かせる（介入警戒圏なら 0.5 くらいに）
python3 usdjpy_model.py --csv data.csv --exception 0.5

# Excel版と完全に同じ数字を出す（感応度を全期間1本にする）
python3 usdjpy_model.py --csv data.csv --beta full

# 教科書的な水準回帰も試す（壊れ方を体験する用）
python3 usdjpy_model.py --csv data.csv --method level

# Webページを出して開く
python3 usdjpy_model.py --csv data.csv --html --open
```

方向性スコアの点数は、`main()` の中の `args.score_inputs` を直接書き換えてください。

## 5つのモジュールが何をしているか

### MODULE 1 — フェアバリューと乖離

```
フェアバリュー = 直近250日の平均レート
               + 感応度 ×（今の金利差 − 直近250日の平均金利差）
乖離zスコア   = （実勢 − フェアバリュー）÷ 直近120日の乖離の標準偏差
```

窓は過去だけを使うので**先読みバイアスはありません**。

`|z| > 2` なら「金利差では説明できないほど行き過ぎ」。
ただし **z が何か月も片側に張り付いているとき**は「いずれ戻る」サインではなく、
「金利差だけでは説明が足りない」サイン（＝構造的な円売りや介入が効いている）です。

> **なぜ「水準どうしの回帰」を使わないのか**
> 金融機関のレポートでよく見る `ドル円 = a + b × 金利差` は、構造的な円売りが強い局面で
> `b` がマイナス（＝金利差が広がると円高、という経済的にありえない推定）になりがちです。
> このモデルは**変化どうしの回帰**から感応度を取り、水準の部分は移動平均に任せています。
> `--method level` で教科書版も走らせられるので、壊れ方を一度見ておくことをおすすめします。

### MODULE 2 — 金利感応度（beta）

日次の `ΔlogFX(%) = a + b × Δ金利差(pt)` を回帰します。この `b` がシナリオ計算の土台です。
R² は 0.05〜0.30 程度が普通で、**残りの7〜9割は金利差以外で動いています**。これが実態です。

### MODULE 3 — イベント・シナリオ

```
利上げした場合のサプライズ = ＋利上げ幅 ×（1 − 織り込み確率）
据え置いた場合のサプライズ = −利上げ幅 × 織り込み確率
金利差の変化 = 伝わり方 ×（米サプライズ − 日サプライズ）
ドル円の変化 = 現在値 × 感応度 ÷ 100 × 金利差の変化
```

**効くのは「決定」ではなく「織り込みとのズレ」**という考え方を、そのまま式にしたものです。
90%織り込まれた利上げが実行されても相場が動かない理由が、この式に入っています。

「利上げ×利上げ」と「据え置き×据え置き」が同じ結果になるのは正しい挙動です。
両国が同じ方向に動くとサプライズが打ち消し合い、金利差は織り込み確率の差だけで決まります。

### MODULE 4 — 方向性スコアリング

5つの材料を −2〜+2 で採点し、重み付き合計を −100〜+100 に換算します。
**例外フィルター**（介入警戒・リスクオフ・ポジション偏り）は方向を持たないので、
足し算ではなく**掛け算で結論を弱める係数**として扱います。

`|スコア| < 20` の「方向感なし」も正しい出力です。
材料が割れているときに無理やり方向を決めるのが、最も損をするパターンです。

### MODULE 5 — 正直なバックテスト

1. 乖離zは、その後20営業日のリターンを説明できるか（傾き・R²・符号の的中率）
2. サンプルの前70%で係数を推定し、**残り30%（モデルが一度も見ていない期間）**で
   ランダムウォーク（＝「動かない」と予想）と予測誤差を比べる

実データでは的中率50〜55%、誤差比率0.95〜1.05あたりに収まるのが普通です。
**それでいい**、というのがこのモジュールの言いたいことです。

## このモデルの限界

**短期の為替は、ランダムウォークに勝つのが極めて難しいことが知られています。**
このツールは「明日いくらになるか」を当てる道具ではありません。

正しい使い方は「**今の水準は金利差で説明できる範囲か、それとも行き過ぎか**」を測ることです。
そして次の局面では、金利差の結論を弱めるか、いったん判断を保留してください。

- **為替介入** — 当局が実弾を入れている局面では、金利差より当局の意思が支配します
- **リスクオフ** — 株が急落すると、金利差が動かないままキャリー取引の巻き戻しで円高になります
- **ポジションの偏り** — 円売りが積み上がるほど、小さな材料で大きく巻き戻します
- **構造的な円売り** — 貿易赤字・デジタル赤字・NISA経由の対外投資は、金利差と無関係に毎月円を売り続けます
- **財政と政治** — 金利差の方程式の外側から効きます
