# 売上原価の蓄積（EDINET DB）

東証の全銘柄について、有価証券報告書ベースの**通期の売上原価（直近4期）**を
EDINET DB の REST API から少しずつ集めて CSV に貯めていきます。

無料プランは **100リクエスト/日** しか使えないので、1日の上限（既定90件）まで
取ったらその日は終了し、**翌日の実行で続きから**再開します。全銘柄（約3,700社）が
埋まるまでの目安は **約41日**です。

## ファイル

| ファイル | 中身 |
|---|---|
| `fundamentals/cost_of_sales_by_year.csv` | 1行＝銘柄×年度（直近4期）。売上高・売上原価・売上総利益・原価率・提出日 |
| `fundamentals/cost_of_sales_latest.csv` | 1行＝銘柄。直近4期を横に並べたもの（スクリーニング用） |
| `fundamentals/cost_of_sales_failed.csv` | 3回試しても取れなかった銘柄 |
| `fundamentals/edinet_companies.csv` | 証券コード→EDINETコードの対応表（月1回だけ取り直す） |
| `fundamentals/edinet_state.json` | 進捗・当日の使用リクエスト数・次に取り直す日 |
| `logs/cost_of_sales_YYYYMM.log` | 実行ログ（3か月より古いものは自動で消えます） |

APIキーは `.edinetdb_key`（本人以外が読めない権限）に置いてあります。

## 自動実行

`install_cost_of_sales_schedule.sh` で launchd に登録済みです。

- 毎日 **08:00 / 21:00**、および Mac のログイン時
- その日の枠を使い切っていれば数秒で終了するので、何度動いても無駄はありません
- **サーバ側の上限に先に当たった場合（429）も、そこで静かに止めて翌日に回します**
  （チャットから EDINET DB を使った日は、90件より手前で止まります）

## 埋め終わったあとの動き

各銘柄について「前回の有報の提出日 ＋ 約1年」を次回の取得予定日として持っています。
本決算が出る頃合いになった銘柄だけを取り直すので、**通期決算が出れば自動で最新の
売上原価が入ります**。3月期決算が集中する6〜7月は対象が多くなりますが、1日90件ずつ
消化していくので、7月中には行き渡ります。

初回収集が終わるまでは、再取得に回す枠は1日の3割までに抑えています（初回収集が
いつまでも終わらなくなるのを防ぐため）。

## よく使うコマンド

```bash
cd ~/株分析
./.venv/bin/python fetch_cost_of_sales.py --status      # 通信せず進捗だけ確認
bash run_cost_of_sales.sh                               # 今すぐ当日の枠ぶん取得
./.venv/bin/python fetch_cost_of_sales.py --probe 7203  # 1社だけ試して生JSONを残す
BUDGET=30 bash run_cost_of_sales.sh                     # その回だけ上限を変える
```

## 注意点

- 売上原価は2026年9月に EDINET DB に追加された項目です。取得できた77社のうち
  72社は4期すべて揃っていましたが、**IFRS採用企業などで直近期が空の場合があります**
  （例: トヨタの FY2024・FY2025）。空だった銘柄は120日後にもう一度見に行きます。
- 売上原価が無く、売上高と売上総利益がある年度は、差し引きで売上原価を埋めています。
- 金額の単位は円（APIの生値そのまま）。会計基準（JP/IFRS/USGAAP）は列に入れてあります。
