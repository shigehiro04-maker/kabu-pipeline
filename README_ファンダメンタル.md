# 東証全銘柄 ファンダメンタルデータ取得ツール

`fetch_fundamentals.py` は、東証プライム・スタンダード・グロースの全銘柄（約3,700）について
決算数値と投資指標を取得し、CSV に出力します。データ元は Yahoo Finance です。

---

## 使い方

```bash
cd ~/株分析

./.venv/bin/python fetch_fundamentals.py                       # 全銘柄（20〜30分）
./.venv/bin/python fetch_fundamentals.py --codes 7203,6758     # 銘柄を指定
./.venv/bin/python fetch_fundamentals.py --markets プライム      # 市場で絞る
./.venv/bin/python fetch_fundamentals.py --years 5             # 5期分出力
./.venv/bin/python fetch_fundamentals.py --refresh             # キャッシュ無視で取り直す
```

決算発表後にデータを更新したいときは `--refresh` を付けて再実行してください。
付けない場合、7日以内に取得済みの銘柄はキャッシュから読むので数秒で終わります。

途中で止めても、取得済みの銘柄は保存されています。もう一度実行すれば続きから進みます。

### 主なオプション

| オプション | 既定 | 説明 |
|---|---|---|
| `--years N` | 3 | 出力する決算期数（Yahooの保有は最大4期） |
| `--workers N` | 4 | 並列数 |
| `--interval 秒` | 0.35 | リクエスト間隔の下限。429が出るなら増やす |
| `--max-age-days N` | 7 | キャッシュの有効日数 |
| `--timeout 秒` | 20 | 1リクエストのタイムアウト |

## 出力ファイル

```
~/株分析/fundamentals/
├── fundamentals_latest.csv    1行 = 1銘柄（最新期）スクリーニング用
├── fundamentals_by_year.csv   1行 = 銘柄 × 決算期（直近3期）推移分析用
├── failed.csv                 取得できなかった銘柄と理由
└── raw/<コード>.json          APIの生レスポンス（キャッシュ）
```

### fundamentals_latest.csv の列

| 分類 | 列 |
|---|---|
| 銘柄情報 | コード、銘柄名、市場、業種、株価、株価日付、決算期、通貨、取得日 |
| 規模 | 時価総額、売上高、総資産、自己資本、発行済株式数 |
| 損益 | 営業利益、税引前利益、当期純利益、営業利益率(%) |
| 財務健全性 | 自己資本比率(%)、流動比率(%)、総資本増加率(%) |
| キャッシュフロー | 営業CF、投資CF、財務CF、フリーCF |
| 一株あたり | BPS、EPS、一株配当、配当利回り(%) |
| バリュエーション | PER、PBR、PSR |
| 成長性 | 売上高_前期／前々期、営業利益_前期／前々期、当期純利益_前期／前々期、売上高成長率(%)、営業利益成長率(%) |

金額はすべて**円**です（億円・百万円ではありません）。Excel で開く場合は表示形式で調整してください。

## 数値の出どころ

| 項目 | 算出方法 |
|---|---|
| 時価総額 | 保存済み終値 × 発行済株式数 |
| 自己資本比率 | 自己資本 ÷ 総資産 |
| 流動比率 | 流動資産 ÷ 流動負債 |
| BPS | 自己資本 ÷ 発行済株式数 |
| EPS | 決算で報告された基本的EPS |
| 一株配当 | 報告値。無い場合は 支払配当総額 ÷ 平均株式数 |
| 配当利回り | 一株配当 ÷ 株価 |
| PER | 株価 ÷ EPS（実績） |
| PBR | 株価 ÷ BPS |
| PSR | 時価総額 ÷ 売上高 |
| 総資本増加率 | 総資産の前期比 |

株価は `data/daily/` の最新ファイル（`fetch_stocks.py` が毎営業日16:30に更新）から読みます。
PER・PBR・PSR・時価総額は、この終値と決算実績から**自前で計算**しています。
Yahoo が持つ既成の指標値は数日前の株価基準でCSVの株価列とずれるため、
自前計算できない場合のフォールバックとしてのみ使用します。

## 取得実績（2026年9月2日時点）

対象3,711銘柄のうち **3,706銘柄** を取得。主要項目の取得率は次のとおりです。

| 項目 | 取得率 | 項目 | 取得率 |
|---|---|---|---|
| 売上高・当期純利益・税引前利益 | 100.0% | 営業CF・投資CF・財務CF | 98.2% |
| 時価総額・PER・PBR | 99.9% | 一株配当・配当利回り | 98.2% |
| 自己資本比率 | 99.9% | 営業利益 | 97.3% |
| BPS・EPS・PSR | 99.8% | 流動比率 | 97.2% |

取得できなかった5銘柄（FUNDINNO、GMSグループ、トランヴィア、MIRAINIホールディングス、
前澤ホールディングス）はいずれも新規上場銘柄で、Yahoo にまだ財務データがありません。

営業利益と流動比率の欠損は、ほぼ銀行・保険・証券によるものです。

**157銘柄は決算期が15か月以上前です。** Yahoo 側の財務データ更新が遅れている銘柄で、
最新期ではなく完全なデータが揃う期を採用しています。スクリーニングの際は「決算期」列で
新しさを確認してください。

## 注意点

**経常利益は取得できません。** Yahoo の標準化財務諸表は国際会計基準ベースで、日本基準特有の
経常利益という区分を持ちません。代わりに **税引前利益** を収録しています。
経常利益がどうしても必要な場合は、JPX公式の J-Quants API（有料プラン）か
EDINET の XBRL からの取得が必要です。

**銀行・保険・証券は一部の列が空欄になります。** 営業利益・流動資産・流動負債の概念が
標準化財務諸表に無いためです（例: 三菱UFJ）。金融銘柄をスクリーニングする際は、
これらの列でフィルタしないでください。

**当期純利益は一時要因を含む報告ベースの値です。** 例えばソニーの2026年3月期は、
金融事業スピンオフの影響で継続事業が1兆円超の黒字にもかかわらず最終赤字となり、
PERがマイナスで表示されます。異常値に見える銘柄は、まず特別損益の有無を疑ってください。

**決算期は銘柄ごとに異なります。** 3月期・12月期などが混在するため、
横断比較する際は「決算期」列を確認してください。

**Yahoo Finance は非公式APIです。** 仕様変更で取得できなくなる可能性があります。
その場合は `./.venv/bin/pip install -U yfinance` を試してください。

## 自動更新（設定済み）

既存の日次ジョブ（平日16:30の `run_daily.sh`）に組み込み済みです。**追加の登録作業は不要**で、
株価の取得が終わったあとに `run_fundamentals.sh` が自動で走ります。

| 曜日 | 動作 | 所要 |
|---|---|---|
| 月・火・木・金 | 通信せず、その日の終値でCSVを作り直す（時価総額・PER・PBR・PSR・配当利回りが最新に） | 約5秒 |
| 水曜 | 上に加えて、**次の本決算が出ているはずの銘柄だけ** Yahoo から取り直す | 約2分（現在280銘柄） |

「次の本決算が出ているはず」とは、CSV上の決算期から400日以上経過している銘柄です
（決算期末から13か月＝日本企業の開示期限45日を大きく超えた時点）。全銘柄を毎回取り直さないので、
通信は最小限で済みます。決算期のバラつき（3月期・12月期など）は自動的に吸収されます。

### 決算が更新された銘柄の記録

新しい決算を検知すると `fundamentals/earnings_updates.csv` に追記されます。

```
検知日, コード, 銘柄名, 市場, 業種, 新決算期, 前決算期,
売上高, 売上高成長率(%), 営業利益, 営業利益成長率(%), 当期純利益, EPS, 一株配当, 自己資本比率(%), 営業CF
```

「今週どの銘柄の決算が出て、前期比でどうだったか」がこのファイルだけで追えます。

### 手動で動かす

```bash
bash ~/株分析/run_fundamentals.sh --due    # 決算の再取得を今すぐ（水曜の動作）
bash ~/株分析/run_fundamentals.sh          # 株価反映のCSV再生成だけ
./.venv/bin/python fetch_fundamentals.py --refresh   # 全銘柄を取り直す（20〜30分）
```

決算発表シーズン（5月・8月・11月・2月の中旬）に取りこぼしが気になるときは、
`--due` を何度か手動実行すれば確実です。

### 通信できなかったとき

水曜の取得中に Yahoo へ繋がらない場合は、取得を見送ってキャッシュからCSVを作り直します。
銘柄が欠けたり前日のデータが壊れたりはしません。翌週の水曜に自動で再挑戦します。

ログは `logs/fundamentals_YYYY-MM-DD.log`（30日で自動削除）に残ります。

### 自動更新を止めたいとき

`run_daily.sh` の「1d) ファンダメンタルの更新」の行をコメントアウトしてください。
株価の日次更新はそのまま続きます。
