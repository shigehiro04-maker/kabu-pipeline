# 寄り前ギャップ（Buy-on-Gap 試験運用）

『Algorithmic Trading』（E. Chan）第4章の Buy-on-Gap を、**お金を入れずに**毎日記録する仕組み。
検証は `../平均回帰_株とETF_第4章_20261010/README_株とETFの平均回帰.md`（2016-12〜 k=1 で年率26%、R/R 0.95、最大DD約37%、コスト前）。

## ルール
| 項目 | 内容 |
|---|---|
| 運用対象 | 前月末に、60日の売買代金の中央値 2億円以上・時価総額 300億円以上の内国株（約1,200銘柄） |
| 買う条件 | 当日始値 < 前日安値 ×（1 − k × σ90）、かつ 当日始値 > 20日移動平均（σ90＝前日までの90日の日次リターンの標準偏差） |
| 買い方 | 条件を満たした銘柄のうち 始値÷前日安値 が小さい順に10銘柄を、寄付きの成行で同額ずつ買い、大引けの成行で売る |
| k | 1（本書の既定・主）と 0.5（参考）の両方を記録 |

## 毎日の流れ（run_daily.sh の 3b-5、通信なし・数十秒）
1. `gap_record.py` … 前の営業日に作った候補を、今日の実際の始値・終値で答え合わせして記録（何度動かしても同じ）
2. `gap_candidates.py` … 今日の引け値で、次の営業日の「買いの価格帯」を全運用対象について作る
3. `gap_page.py` … 画面 `data/charts/gap.html`（トップ画面のカード「寄り前ギャップ」から）と要約 `gap_summary.json`

## 翌朝の使い方（8:50〜8:59）
画面の候補表で、寄り前の気配が **下限（20日線）より上・上限より下** の銘柄が条件成立。10銘柄を超えたら 気配÷前日安値 が小さい順。
寄らず・ストップ安は買わない。大引けで必ず売る。
※ 寄り前の気配と実際の始値はずれることがある。試験運用の記録は「実際の始値で買えた」とした場合の値。

## ファイル
| ファイル | 中身 |
|---|---|
| `output/candidates/<判断日>.csv` | 運用対象の全銘柄の 前日安値・σ90・20日線・上限（k=1, 0.5）・候補フラグ |
| `output/record_trades.csv` | 試験運用の取引（日付・k・順位・銘柄・始値・終値・ギャップ・損益） |
| `output/record_daily.csv` | 試験運用の日次（条件を満たした数・買った数・損益・TOPIX寄り引け・ヘッジ後） |
| `output/replay_*.csv` | `replay_check.py` で過去1年（2025-10〜）を同じスクリプトで再現した結果（試験運用とは別） |
| `gap_common.py`, `gap_core.py` | 共通部品（ルールはここ） |

## 再現の確認（replay_check.py）
本番のスクリプトで 2025-10-01〜2026-10-09 を1日ずつ（その日までの株価だけで）流した結果、検証の日次と **相関 0.99**（k=1）・**0.999**（k=0.5）。
過去1年の再現: k=1 累計 +29.4%（373取引、1取引平均 +64bp、勝率57%）、k=0.5 累計 +66.8%（1,190取引、+41bp、55%）。いずれもコスト前。

## 追加（2026-10-12）：売り側と「決算翌日」の印
第7章の検証（`../日中モメンタム_第7章_20261012/`）を受けて、**買い側のルールは変えずに**次の2つを紙の記録に加えた。条件と判定基準は `PREREG_売り側と決算印.md` に固定（2026-10-13 の寄付きから記録）。

| 追加 | 中身 |
|---|---|
| 売り側（上の窓を売る） | 当日始値 > 前日高値 ×（1 + k × σ90）かつ 始値 < 20日線 の銘柄を、始値÷前日高値 が大きい順に10銘柄、寄りで売り引けで買い戻す（k=1 主、0.5 参考）。画面は `data/charts/gap_short.html`（買い側の画面の上のリンクから） |
| 決算翌日の印 | 判断日〜対象日の前日に決算発表（予定）がある銘柄に「決算」の印。日次の記録に「決算翌日を除いて選んだ場合」の損益を並べる |

過去の再現（本番のスクリプトで 2016-12〜2026-10、コスト前）：売り k=1 年率 +39%・シャープ 1.53・最大DD −25%・1取引平均 +47bp。買い k=1 との日次相関 −0.03、半々で合成するとシャープ 1.84。

### 毎日の流れに追加（run_daily.sh の 3b-5 の後半。失敗しても買い側には影響しない）
4. `gap_short_record.py` … 売り側の答え合わせ（`output/record_short_trades.csv`, `record_short_daily.csv`）
5. `gap_short_page.py` … 売り側の画面

候補ファイル `output/candidates/<判断日>.csv` には、`前日高値`・`売り下限_k1`・`売り候補_k1`（0.5も）・`決算翌日` の列が増えた。

### 決算発表予定日のファイル
毎日の処理の最初（run_daily.sh の 3b-5a）で `fetch_kessan_schedule.py` が JPX「決算発表予定日」のページから Excel（kessanMM_MMDD.xlsx）を取り、
`株分析/決算発表予定日/` に保存する（2026-10-12 承認・無料。新しいか中身が変わったものだけ。古い版は消さない）。
手で `株分析/` に置いた kessan*.xlsx も読む（同じ決算期は「現在」日付の新しい版を使う）。
処理ログ（logs/gap.log）の「予定表の最終日」がその先の日付になっていれば足りている。過去分は J-Quants 決算サマリーの開示日も使う。
